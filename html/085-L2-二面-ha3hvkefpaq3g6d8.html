三：场景题

在多实例部署的系统里，如何设计 Access Token 的缓存和刷新机制。

​

详细题目：你的系统调用第三方业务接口前，必须先拿 Access Token。这个 Token 有效期为 8 小时，过期后要刷新；但每次刷新后，旧 Token 会立刻失效。系统又是多实例部署，多个实例可能同时调用第三方接口。

所以问题就是：

怎么保证多个实例都能拿到可用 Token，同时避免多个实例同时刷新 Token，导致旧 Token 失效、请求失败？

核心考点：

  1. Token 放哪里缓存？
  2. 什么时候刷新？
  3. 多实例同时刷新怎么处理？
  4. 刷新后旧 Token 立即失效怎么处理？
  5. 正在请求时 Token 被别的实例刷新了怎么办？
